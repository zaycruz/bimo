# Bimo v0.7.0 (proposed)

Status: draft. Not tagged or published; publishing waits on operator approval
and the open-core licensing decision.

## Highlights

- **The Bimo engine.** The Rust runtime fabric is now part of Bimo, in
  `engine/` (crate and binary `bimo-engine`, with its full history). It places
  spec-declared Hermes and eve agents on the local machine or a Proxmox cluster
  through the Proxmox API, keeps a per-tenant warm pool of guests, and runs each
  agent behind its own credential proxy, so the agent holds only placeholders
  for its secrets. See [docs/engine.md](../engine.md).
- **`bimo` drives the engine.** `bimo agent validate|plan|apply|status|logs|destroy|list`,
  `bimo pool status|fill|drain`, `bimo proxy up|status|down` and
  `bimo engine ARGS...` run `bimo-engine` with a validated argv, no shell and a
  bounded run time (`BIMO_ENGINE_TIMEOUT_MS`). The in-container
  `bimo agent --...` and `bimo proxy --...` forms and every existing command
  are unchanged.
- **Deployment manifests reach the engine.** A deployment manifest may now
  declare `target: {kind: "engine", name: "<target>"}` with a Hermes
  configuration directory and a `TENANT/NAME` secret handle.
  `bimo plan` reports it as `executionSupported: true`, and
  `bimo agent apply MANIFEST.json` renders it into an engine spec under
  `.bimo/specs/` and applies it. `examples/deployments/engine-hermes.json` is
  the reference.
- **Bimo names, old names kept.** Operator settings are `BIMO_*`
  (`BIMO_SECRET_<TENANT>__<NAME>`, `BIMO_STATE_ROOT`, `BIMO_HERMES_BIN`, ...)
  and local state is `.bimo/`. The prototype's earlier variable names and
  state directory still work, and names baked into the golden template and
  running guests are unchanged (see `engine/docs/naming.md`). JSON envelopes
  now carry the schema `bimo.cli/v1`.

## Fixes

- The engine now makes its state root absolute before it starts a credential
  proxy. With the default relative root, iron-proxy could not find its
  configuration and every local apply failed with `proxy_failed`.
- `engine/scripts/e2e-tools.sh` installs `aiohttp==3.13.3` with the pinned
  hermes-agent. Without it, Hermes' API server did not start on a fresh
  checkout and 7 of the 11 local fabric E2E tests failed with `probe_failed`.
- `bimo service` on an engine-target manifest now says to use `bimo agent`.
- `engine/scripts/build-template.sh` requires `PARK_IP` and `GATEWAY` instead
  of defaulting to one cluster's addresses.

## Test results

Recorded results, not guarantees. Each was measured on one Proxmox cluster
with the v4 golden template, and will vary with hardware and network.

| Measurement | Result | Target | Source |
| --- | --- | --- | --- |
| Hermes warm apply-to-first-task | p50 802 ms, p95 856 ms (6 warm claims) | p95 under 1000 ms: met | `20261009T165658Z-spawn-latency-86108` |
| eve pooled apply-to-first-task | p50 1374 ms, p95 1397 ms | p95 under 1000 ms: **missed** | `20261009T165658Z-spawn-latency-86108` (suite status FAILED for this reason) |
| Per-tenant proxy isolation on Proxmox | PASS | one tenant's guest cannot connect to another tenant's proxy guest; another tenant's credential, a forged token and no credential are refused (407); a spec naming another tenant's secret handle is refused | `20261009T161358Z-proxmox-agents-50427` (suite PASSED) |
| Warm pool tenant separation | PASS | a claim never takes another tenant's warm guest | `20261009T165658Z-spawn-latency-86108` |

The isolation run used a shared bridge with no per-tenant VLANs: separation is
enforced by per-route credentials and source addresses at each tenant's proxy
front and by each agent guest's firewall lock. Per-tenant VLANs
(`tenant_vlans`) are supported but were not part of that run.

The method and earlier runs are in
[engine/docs/benchmarks/spawn-latency.md](../../engine/docs/benchmarks/spawn-latency.md).
The live suites run only with `BIMO_PROXMOX_LIVE=1` and an operator's targets
file; CI does not run them.

Local checks for this release (no live substrate):

- `npm test` (Node suite)
- `cargo test --manifest-path engine/Cargo.toml` (live suites skip)
- `sh engine/tests/acceptance_worker.sh`, `sh engine/tests/acceptance_fabric.sh`
- `node test/engine-proof.mjs`: real `bimo`, `bimo-engine` and Hermes on the
  local target, from a deployment manifest to a first accepted task and back;
  writes `engine/target/e2e-bimo/<run>/report.json`

## Upgrade notes

- The npm package does not ship the engine. Build it with
  `cargo build --release --manifest-path engine/Cargo.toml`, or set
  `BIMO_ENGINE_BIN` to an installed `bimo-engine`.
- Rename variables to `BIMO_*` at your own pace; the prototype's names keep
  working, and a targets file may keep its existing `token_env`.
- Automation that matched the prototype's envelope schema string must match
  `bimo.cli/v1`. The envelope's fields are unchanged.

## Known limits

- eve misses the 1 s readiness target (above).
- Engine agents from deployment manifests are Hermes services with an
  OpenRouter key; eve needs an engine spec. Manifest `limits` are not applied
  to engine agents; the target configuration sizes guests.
- The guest-side variable names, paths and Proxmox ownership tag keep the
  prototype's names until the next template version
  (`engine/docs/naming.md`).
